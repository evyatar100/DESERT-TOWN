# Desert Town characters

Donor records live in `asset_generation/production/char/<donor>/<name>-<id>/metadata.md`. One folder is one character. The 8-hex suffix after the last hyphen is the character id (`זיג-זאד-11eaf4fa` → `11eaf4fa`).

A character may stand on more than one map. Each standing spot is its own map event and its own row in the location ledger. The spoken line and the name are not stored on the event.

## Sources of truth

| Fact | File | Edited by |
|---|---|---|
| Name, camp, line, description, abilities, flags | `metadata.md` | Donor record. Do not rewrite it to record a map location. |
| Where a character stands | `asset_generation/characters/locations.json` | Every placement change |
| English and Hebrew name and lines | `game-files/PBS/translations.json` | New `NAME_<ID>` and `MSG_<ID>_…` keys |
| What the player sees in the catalog | `asset_generation/characters/catalog.html` | Generated only. Never hand-edit. |

Field list, ledger schema, and translation keys: [reference.md](reference.md).

Skip `dt148_qa_field_1786427980` (`e98a1184`) unless the user explicitly asks to place the QA character.

## How a placed character behaves

One RPG Maker XP event per standing spot.

- Event name: `dt_<id>` (example `dt_11eaf4fa`).
- Trigger: Action Button. The player faces the event and confirms.
- Graphic: `game-files/Graphics/Characters/dt_<id>.png`. Match the cell size and 4×4 direction layout of an existing charset in that folder.
- The event starts with the speaker, then the line:

```ruby
pbDesertSpeaker("11eaf4fa")
pbDesertTalk("11eaf4fa")
```

`pbDesertSpeaker` is the per-character setup. It opens a name plate on the outer edge of every following message window (above it when the box sits in the lower half of the screen) until the event finishes. `pbDesertTalk` only looks up the character and calls `pbMessage(_INTL("MSG_<ID>_LINE"))`. It does not set or clear the speaker. The name is a translation key, so HebrewSupport draws it. Do not put the name inside the message string.

A different line at one spot:

```ruby
pbDesertSpeaker("11eaf4fa")
pbDesertTalk("11eaf4fa", "MSG_11EAF4FA_KUSUMO")
```

Further lines in the same event are more `pbDesertTalk` calls, Show Text (101/401), or `pbMessage` commands. They keep the plate. The speaker clears automatically when the event finishes, so it never leaks onto the next event's text. Call `pbDesertSpeaker` again with another id to switch speaker mid-event.

Extra actions (a choice, an item, a transfer) are normal Essentials script on that same event page, after `pbDesertTalk`. Record a short label in the placement's `actions` array so the catalog can list it. Do not invent a second scripting language in the JSON.

## Name plate plugin

Implement this once, in `game-files/Plugins/DesertTalk/`, not by editing `Data/Scripts.rxdata`.

- `meta.txt` follows `game-files/Plugins/BurningManBag/meta.txt` (`Essentials = 21.1`).
- `characters.rb` is generated by `build_catalog.py`. It is a hash of character id → `name_key` and default `line_key`. Do not hand-edit it.
- `pbDesertTalk` only shows the character's line. `pbDesertSpeaker` sets the name without a message; an `:on_frame_update` handler clears it once the map interpreter stops running (the event has ended).
- Hook `pbCreateMessageWindow` / `pbDisposeMessageWindow` (HebrewSupport already wraps `pbMessage`). Draw the translated name through the normal window text path so Hebrew RTL still applies.
- After any plugin edit, from `game-files/`: `python compile_plugins.py`.

## Place a character

1. Read that character's `metadata.md`. If **Quest usable** is `no`, say so before placing.
2. Resolve the map in `game-files/PBS/map_metadata.txt` (`[094]` is map id 94, file `game-files/Data/Map094.rxdata`).
3. Pick a free tile. Do not stack two events on one tile.
4. Add translation keys (see [reference.md](reference.md)). Copy the metadata line into `he`. Use **Name (English)** / an existing English line for `en`. If no English text exists, put the Hebrew text in `en` too. Do not invent dialogue.
5. Add the charset `dt_<id>.png` if it is missing.
6. Add the event. Copy `MapNNN.rxdata` to `MapNNN.rxdata.bak` first. `RPGXP.exe` must be closed (`Get-Process RPGXP -ErrorAction SilentlyContinue`). Prefer cloning an existing event on that map and changing id, name, x, y, graphic, and the script line. `rubymarshal` can fail on these maps with `invalid link destination`; if it does, stop and place the event in RPG Maker XP, then record the ids. Do not hand-patch marshal bytes.
7. Append one object to `locations.json`. `line_key` is `null` when the spot uses the default line.
8. Rebuild the catalog:

```bash
python asset_generation/characters/build_catalog.py
```

9. From `game-files/`, run `python validate_translations.py` and `python test_event_translations.py`.

Reload the map file and confirm the new event starts with `pbDesertSpeaker` then `pbDesertTalk`, both with the right id. The catalog must list the new spot and must not list the character under unplaced.

## Catalog page

`catalog.html` is generated by `python asset_generation/characters/build_catalog.py`. Do not hand-edit it. Open `asset_generation/characters/catalog.html` in a browser.

Until `locations.json` has placements, the page lists production characters and the first frame of each `sheet.png` (top-left 32×48 cell of the 128×192 charset). Portraits are embedded in the file. It does not show map stops. Skip the QA character `e98a1184`.

When the ledger has placements, regenerate and show each standing spot (map name, map id, event id, x, y, line override, actions) on that character. Do not add a stops section while the ledger is empty.
